# Week3. ☕ 커피 배달 게임 — 프롬프트 구조화 실습

**이미 만들어진 게임을 출발점으로, AI에게 원하는 변경을 정확하게 요청하는 수업입니다.**
코드를 전부 이해할 필요는 없습니다. 무엇을 바꿀지 설명하고, 결과를 직접 확인하는 것이 목표입니다.

곰돌이가 우주 정거장 카페에서 커피 여섯 잔을 받아 여섯 이웃에게 배달하고, 카페로 돌아와 평가를 받는 작은 3D 게임입니다.
생명은 하트 3개입니다. 3초 뒤 폭발하는 외계 고양이와, 표시된 자리에 별 네 개를 떨어뜨리는 UFO에 맞으면 하트가 하나씩 줄어듭니다.
게임은 `index.html` 하나로 실행됩니다. 게임 실행에는 설치, 서버, API 키가 필요 없습니다.
AI로 수정하는 과정에는 수업에서 사용하는 AI 도구가 별도로 필요합니다.

## 1. 내 컴퓨터에서 게임 열기 

1. [이 저장소](https://github.com/Sjsj-prompt/coffee-delivery-game-week3) 위쪽의 초록색 **Code** 버튼을 누릅니다.
2. **Download ZIP**을 눌러 다운로드합니다.
3. ZIP 파일의 압축을 풉니다. 압축 파일 안에서 바로 열지 마세요.
4. 폴더 안의 **index.html**을 Chrome, Edge, Safari 등 브라우저로 엽니다.
5. **시작 / 계속** 버튼을 누르고 게임을 해봅니다.

> GitHub에서 `index.html`을 클릭하면 코드가 보입니다. 게임은 다운로드한 파일을 브라우저로 열어야 실행됩니다.

### 게임 조작 방법

| 하고 싶은 일 | 조작 |
|---|---|
| 시작하거나 계속하기 | 화면 아래 `시작 / 계속` |
| 이동하기 | 방향키 또는 W / A / S / D |
| 커피 받기·전하기 | 카페나 이웃 가까이에서 E 또는 Space |
| 잠깐 멈추기 | 화면 아래 `잠깐 멈추기` |
| 새로 시작하기 | 화면 아래 `처음으로` |

화면 아래 방향 버튼으로도 이동할 수 있습니다. 안내 화살표를 따라 카페에서 커피를 받으면 이웃들이 나타납니다. 여섯 곳에 모두 배달한 뒤 카페로 돌아가면 완료됩니다. 다른 창으로 이동하면 게임이 멈출 수 있으니 돌아와서 `시작 / 계속`을 누르세요.

## 2. 오늘 배울 것

같은 AI라도 요청이 모호하면 원하지 않은 부분까지 바꾸거나, 필요한 조건을 빠뜨릴 수 있습니다.
오늘은 프롬프트를 다음 다섯 칸으로 나눠 작성합니다.

| 칸 | 쉽게 말하면 | 예시 |
|---|---|---|
| 현재 상황 | 지금 무엇이 있나요? | HTML 한 파일로 만든 커피 배달 게임 |
| 목표 | 무엇이 달라지면 좋나요? | 처음 하는 사람도 조작법을 쉽게 찾기 |
| 구체적인 변경 | 어디를 어떻게 바꾸나요? | 아래 안내 문구의 글자 크기를 16px로 변경 |
| 유지할 것 | 무엇을 건드리지 않나요? | 이동 방식, 배달 규칙, 마을 모양 |
| 완료 기준 | 무엇을 보면 성공인가요? | 안내가 잘 읽히고 기존 게임이 그대로 실행됨 |

**좋은 프롬프트는 긴 프롬프트가 아니라, 원하는 결과를 확인할 수 있는 프롬프트입니다.**

## 3. 첫 실습: 막연한 요청과 구조화한 요청 비교 

### 준비

압축을 푼 원본 폴더를 두 번 복사해 `before`와 `after` 폴더를 만드세요.
두 폴더 모두 같은 원본 `index.html`에서 시작합니다. 원본 폴더는 남겨둡니다.

AI 코딩 도구를 사용한다면 해당 폴더를 열고, 채팅형 도구라면 해당 `index.html`을 첨부하세요.
A와 B는 각각 새 대화에서, 같은 모델과 설정으로 실행합니다.

### A. 막연하게 요청하기

`before` 폴더의 파일을 대상으로 다음을 요청합니다.

```text
이 커피 배달 게임의 조작 안내를 더 보기 좋게 만들어줘.
```

AI가 만든 파일을 저장하고 브라우저에서 열어봅니다.
글자 크기, 문구, 위치가 어떻게 바뀌었는지 적어두세요.

### B. 구조화해서 요청하기

`after` 폴더의 원본 파일을 대상으로 새 대화에서 다음을 요청합니다.

```text
[현재 상황]
첨부한 index.html은 커피를 받아 네 이웃에게 배달하는 게임이다.
HTML 파일 하나로 브라우저에서 실행된다.

[목표]
처음 플레이하는 사람이 화면 아래에서 조작 방법을 쉽게 읽게 하고 싶다.

[구체적인 변경]
1. 화면 아래 조작 안내를 다음 문구로 바꿔줘.
   “① 시작 누르기 → ② 방향키로 이동 → ③ 카페에서 E로 커피 받기 → ④ 이웃 앞에서 E로 배달하기”
2. 이 안내 문구의 글자 크기를 16px로 하고 진한 갈색으로 표시해줘.
3. 좁은 화면에서는 문구가 줄바꿈되게 해줘.

[유지할 것]
게임 속 마을, 캐릭터, 이동 속도, 배달 규칙, 버튼 기능은 유지해줘.
외부 라이브러리나 API를 추가하지 마.
파일을 나누지 말고 index.html 하나로 실행되게 해줘.

[완료 기준]
- 안내 문구가 요청한 순서와 글자 크기로 보인다.
- 화면이 좁아도 안내가 잘리지 않는다.
- 시작, 이동, 커피 받기, 배달, 일시정지, 초기화가 계속 작동한다.

[결과물]
파일을 직접 편집할 수 있으면 index.html을 수정해줘.
직접 편집할 수 없다면 생략 없이 전체 HTML 코드를 제공해줘.
끝에 변경한 점과 직접 확인하지 못한 점을 짧게 알려줘.
```

### 결과를 파일에 반영하기

- AI 도구가 파일을 직접 수정했다면 저장한 뒤 브라우저를 새로고침하세요.
- 코드를 답변으로 받았다면 코드 편집기에서 해당 폴더의 `index.html`을 열고 전체 내용을 교체해 저장하세요. 코드 블록의 시작·끝 표시인 세 개의 백틱은 복사하지 않습니다.
- 파일 이름이 `index.html.txt`가 되지 않았는지 확인하세요. 서식 있는 문서로 저장하면 안 됩니다.
- AI가 “완료했다”고 말한 것과 실제 게임이 작동하는 것은 별개입니다. 직접 눌러보세요.

### A와 B 비교하기

| 확인할 점 | A: 막연한 요청 | B: 구조화한 요청 |
|---|---|---|
| 내가 원한 문구·크기가 적용되었나요? | | |
| 원하지 않은 곳도 바뀌었나요? | | |
| 기존 조작이 유지되나요? | | |
| 추가 설명을 몇 번 해야 했나요? | | |

B가 반드시 더 좋은 결과를 내는 것은 아닙니다. 실제 결과를 보고 **어떤 조건이 도움이 되었고, 어떤 조건이 더 필요한지** 설명해보세요.

## 4. 내 아이디어로 게임 고도화하기 

아래에서 하나만 골라 다섯 칸 프롬프트로 요청하세요. 여러 기능을 한 번에 추가하지 않는 것이 좋습니다.

| 난이도 | 아이디어 | 완료 기준의 예 |
|---|---|---|
| 쉬움 | 버튼을 더 크게 만들기 | 모든 버튼 높이가 44px 이상이며 조작 유지 |
| 쉬움 | 게임의 인사말 바꾸기 | 시작·배달 성공·완료 문구만 바뀜 |
| 보통 | 배달 완료 목록 추가 | 배달할 때 해당 이웃에만 완료 표시, 초기화 시 지워짐 |
| 보통 | 배달 점수 추가 | 처음 배달할 때만 10점, 총 40점, 중복 점수 없음 |
| 도전 | 제한 시간 추가 | 시작 시 감소, 일시정지 중 정지, 시간 종료 처리, 초기화 시 복원 |

복사해서 빈칸을 채우세요.

```text
[현재 상황]
현재 게임은 ...

[목표]
플레이어가 ... 할 수 있으면 좋겠다.

[구체적인 변경]
1. ...
2. ...

[유지할 것]
...는 그대로 유지한다.
외부 라이브러리·API 없이 index.html 하나로 실행되게 한다.

[완료 기준]
- ...하면 ...가 보여야 한다.
- ...할 때는 ...가 바뀌면 안 된다.
- 처음으로 버튼을 누르면 ...가 초기 상태로 돌아와야 한다.

[결과물]
수정된 파일과 변경 요약을 제공한다.
직접 확인한 것과 확인하지 못한 것을 구분한다.
```

## 5. 결과가 이상하면 이렇게 후속 요청하기

“안 돼요” 대신 **한 행동 → 실제 결과 → 기대 결과**를 알려주세요.

```text
[문제 재현]
1. 시작을 누른다.
2. 카페에서 커피를 받는다.
3. 첫 이웃에게 배달하고 E를 한 번 더 누른다.

[실제 결과]
이미 배달한 이웃인데 점수가 다시 10점 올라간다.

[기대 결과]
각 이웃에게 처음 배달할 때만 점수가 올라가야 한다.

[수정 범위]
중복 점수 문제만 고쳐줘. 다른 게임 기능과 디자인은 유지해줘.
수정한 이유와 다시 확인할 방법을 알려줘.
```

위 사례는 **점수 기능을 추가한 뒤 생길 수 있는 가상의 오류**입니다. 기본 게임에는 점수 기능이 없습니다.

[실습 기록지](조준혁.md)를 복사해서 작성하고 패들릿에 제출하세요. 

- 수정한 `index.html`
- 처음 요청한 프롬프트와 최종 프롬프트
- 변경 전·후 화면 또는 짧은 플레이 영상
- 직접 확인한 항목과 아직 남은 문제
- “다음에는 프롬프트에 어떤 조건을 더 쓰겠는가?” 한 문장

GitHub를 사용하는 학생은 이 저장소를 **Fork**해 자기 계정의 복사본을 만들고, 그 저장소에 결과를 올려 링크를 제출할 수도 있습니다. 원본 수업 저장소를 직접 수정할 필요는 없습니다.

## 막혔을 때

- **코드만 보여요:** GitHub 미리보기가 아닌 다운로드한 `index.html`을 브라우저로 여세요.
- **바꿨는데 그대로예요:** 파일을 저장했는지, `before`와 `after` 중 맞는 파일을 열었는지 확인하고 새로고침하세요.
- **이동이 안 돼요:** `시작 / 계속`을 누르고 게임 화면을 클릭해보세요.
- **E를 눌러도 배달이 안 돼요:** 카페에서 커피를 받았는지, 이웃 가까이에 있는지 확인하세요.
- **게임이 안 떠요:** 보관한 원본으로 먼저 실행해보세요. 수정본과 비교해 한 번에 한 가지 변경부터 다시 요청하세요.

## 파일을 조금 더 알아보고 싶다면

| 파일·코드 | 역할 |
|---|---|
| `index.html` | 화면, 디자인, 게임 동작이 모두 들어 있는 실행 파일 |
| `<style>` | 버튼·배경·안내 문구의 모양 |
| `SITES` | 카페와 마을 건물 정보 |
| `newGame` | 게임 초기 상태 |
| `interact` | 커피 받기와 배달 |
| `step` | 이동과 시간 흐름 |
| `draw` | 게임 화면 그리기 |
| `mount` | 키보드 입력과 실행 연결 |
| `조준혁.md` | 실습 기록지 |
| `tests/game.test.cjs` | 기본 배달 규칙을 확인하는 개발자용 테스트 |

건물 수를 늘리는 실습은 여러 곳의 배달 수·표시·완료 조건을 함께 바꿔야 하므로 도전 과제로 남겨두세요. 기본본의 일부 마을 이름은 영어로 표시됩니다.

Node.js가 이미 설치된 사람은 선택적으로 아래 명령을 실행할 수 있습니다. 게임 실행에 필요한 단계는 아닙니다.

```sh
node --test tests/game.test.cjs
```

이 테스트는 게임 상태와 배달 규칙을 확인합니다. 화면 배치나 실제 키보드 조작까지 확인하지는 않으므로 직접 플레이도 해보세요.
